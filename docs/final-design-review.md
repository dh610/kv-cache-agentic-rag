## 구현과의 차이 — 계약 v2 반영

2026-09-22 10:34 피드백 이후 공통 State·8단계 서브그래프·verdict·수정 1회·검색 평가 실행기·등급 어휘·출처 관계·PDF 출력·그래프 최종 검사를 반영했습니다.
항목별 실제 구현 경로와 확인 방법은 [정합성 반영표](design-alignment.md#반영-범위)를 기준으로 확인합니다.

남은 차이는 숨기지 않습니다:

- 종합 뒤 자동 보완은 앞선 사용자 결정대로 0회. 제출 설계의 1회 루프와의 차이는 팀 결정 필요.
- 목록 입력으로 모든 질문을 처리하며 Sub State의 search_count는 질문별 dict. 원 설계의 단일 질문 호출/int와 표현은 다르나 질문별 3회 예산은 유지.
- target 2편 기본 corpus. reference 2편의 등록·판본 확인은 자료 보강 작업으로 남음.
- 도메인 target-only 및 이해관계자의 경쟁 진영 한정 reference 필터를 반영. reference 원문을 등록해야 실제 보조 검색 결과가 생김.
- 기술 TRL은 1~9 어휘/구조와 인용 검사를 갖췄으나 원문·시장 근거에 따른 실제 판단과 검수는 담당자 작업. 김계원님의 기술 프롬프트/TRL 회귀 평가 사례는 PR #4로 먼저 병합되어 이번 계약과 통합. TRL 세부 단계는 해당 프롬프트의 실습 가이드 정의를 유지.
- 30문항의 사람 검증과 실제 모델 비교는 미완료. 실행기를 만들었다고 성능 기준을 통과한 것은 아님.
- 위 평가 해석 쟁점은 여전히 팀 검토 대상. 등급 이름 통일과 판정 조건 합의는 구분.
- PDF 생성 경로는 구현했지만 mock/자동 파일을 제출용 최종 평가로 간주하지 않음.
- 평가 종합(C.3 TRL 확정, C.7 상충 보존, E.2 5장): rubric·프롬프트·종합 전용 계약 검사·검토자 사례를 반영. 시장 직접 근거에 의한 TRL 상향은 검증된 웹 자료가 없어 단위 테스트로만 확인. 상위에 확인 불가가 하나라도 있으면 종합은 needs_revision이며, 공통 `verify`는 unverified가 있으면 fix 단계를 건너뛰므로 종합의 계약 오류는 수정 없이 확인 불가로 보류됨(서브그래프 담당과 순서 검토 필요). 실제 LLM 실행 결과는 아직 없음. 세부는 [종합 노드 점검](synthesis-evaluation.md#5-남은-간극과-하위-노드-영향).
