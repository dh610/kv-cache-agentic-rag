## 구현과의 차이 — 계약 v2 반영

2026-09-22 10:34 피드백 이후 공통 State·8단계 서브그래프·verdict·수정 1회·검색 평가 실행기·등급 어휘·출처 관계·PDF 출력·그래프 최종 검사를 반영했습니다.
항목별 실제 구현 경로와 확인 방법은 [정합성 반영표](design-alignment.md#반영-범위)를 기준으로 확인합니다.

남은 차이는 숨기지 않습니다:

- 종합 뒤 자동 보완은 설계서 표 13대로 1라운드 구현(`supplement` 노드). 등급 조건 해석 쟁점은 여전히 미해결.
- 목록 입력으로 모든 질문을 처리하며 Sub State의 search_count는 질문별 dict. 원 설계의 단일 질문 호출/int와 표현은 다르나 질문별 3회 예산은 유지.
- target 2편 + reference 2편(TurboQuant·InfiniGen)을 등록. 로컬 공유 PDF 기준 전체 71페이지, 본문 54페이지. PDF 네 편 준비 후 인덱스 재생성 필요.
- 도메인 target-only 및 이해관계자의 경쟁 진영 한정 reference 필터를 반영. reference 원문을 등록해야 실제 보조 검색 결과가 생김.
- 기술 TRL은 1~9 어휘/구조와 인용 검사를 갖췄으나 원문·시장 근거에 따른 실제 판단과 검수는 담당자 작업. 김계원님의 기술 프롬프트/TRL 회귀 평가 사례는 PR #4로 먼저 병합되어 이번 계약과 통합. TRL 세부 단계는 해당 프롬프트의 실습 가이드 정의를 유지.
- 30문항의 사람 검증과 실제 모델 비교는 미완료. 실행기를 만들었다고 성능 기준을 통과한 것은 아님.
- 위 평가 해석 쟁점은 여전히 팀 검토 대상. 등급 이름 통일과 판정 조건 합의는 구분.
- PDF 생성 경로는 구현했지만 mock/자동 파일을 제출용 최종 평가로 간주하지 않음.
- 보고서 생성 노드는 E.2 목차(SUMMARY, 1~6장, REFERENCE)와 E.3 절-State 대응으로 조립하며 1·2장은 설계서 서술을 고정 렌더링. REFERENCE는 논문·특허·웹 형식(표 18)을 따르며 논문 권(호)·페이지는 `data/documents.yaml`의 `citation_id`에서 오므로 게재본 확인 후 갱신 필요. 남은 차이: 절별 구성 판정 문장이 본문에 남아 제출 전 사람이 정리해야 함. 상세는 [보고서 노드 문서](report-node.md).
- 평가 종합(C.3 TRL 확정, C.7 상충 보존, E.2 5장): rubric·프롬프트·종합 전용 계약 검사·검토자 사례를 반영. 시장 직접 근거에 의한 TRL 상향은 검증된 웹 자료가 없어 단위 테스트로만 확인. 상위에 확인 불가가 하나라도 있으면 종합은 needs_revision이며, PR #15의 공통 `verify` 변경으로 미확인 항목이 있어도 계약·표현 오류를 먼저 최대 1회 수정하며, 남은 미확인은 보존함. 실제 LLM 실행 결과는 아직 없음. 세부는 [종합 노드 점검](synthesis-evaluation.md#5-남은-간극과-하위-노드-영향).

시장 C.4와 표 8의 등급 조건은 기존 파일과 같으며, 생태계 확인 불가 행은 물리 11쪽으로 이어집니다.
이 절이 앞선 시장 규칙 해석·보완 기록보다 우선하며, 다른 역할에 대한 기존 검토는 별도입니다.

- 시장 rubric의 네 등급 조건을 표 8의 내용으로 교체했습니다. 성장성 높음에 임의의 성장 방향·독립 원 출처 자격을 추가하지 않습니다.
- C.2의 애매하면 낮은 등급, C.4의 계획만 확인되면 한 등급 하향을 프롬프트에 반영했습니다.
- 출처 수와 축소 전망 조건이 함께 성립하면 C.2로 낮은 등급을 선택하고, 상충만으로 확인 불가로 돌리는 이전 규칙을 제거했습니다.
- 논문·데모/원 저자 코드 근거는 있으나 추가 적용·지원이 확인되지 않으면 표 8의 낮음을 적용합니다. 외부 사례 부재의 명시적 증명을 추가로 요구하지 않습니다.
- 평가 근거 자체가 없으면 C.2와 표 8에 따라 확인 불가입니다. 낮음 판정을 해도 확인 범위·미확인은 숨기지 않습니다.
- 정식 도입 1건을 자동 보통에 넣는 별도 매핑은 제거했습니다. 설계서가 개별 경계 사례를 모두 열거하지 않으므로 표 조건과 C.2에 따른 판단 사유를 기록합니다.
- 이해당사자 표시·직접/배경 구분·인용 ID 보존은 유지했고 합성 기대값을 갱신했습니다.

시장 프롬프트·rubric을 제출본 규칙으로 정렬한 것이며 실제 LLM 준수나 전체 설계 구현 완료를 의미하지 않습니다.
양쪽 검색의 수행 보장, 공통 그래프·State·종합·보고서 구현은 시장 담당 변경 범위 밖입니다.

## 1~4단계 재검토에서 발견한 오류 수정

표 8의 등급 조건 12개는 그대로 유지하고, 설계서에 없는 '계획이 실현됐다고 가정해 하향 전 등급 계산' 절차를 제거했습니다.
출시 계획 1건의 하향 전 등급은 설계서에 명시되어 있지 않으므로 planned-only를 실제 제품 출시 계획 사례로 바꾸고,
채택 기대값은 expectations.json에서만 null과 검토 이유로 표시했습니다. 자동 등급 정답으로 사용하지 않으며 실제 NodeResult의 네 등급 계약은 유지합니다.
supported는 서로 다른 도입 A-01·정식 기능 출시 C-02를 명시하고 채택 기대값을 높음으로 바로잡았습니다.
missing-metadata는 실험적 프레임워크·커뮤니티 구현의 지원·버전·범위가 명확하고 날짜만 누락된 사례로 변경했습니다.
지원 근거에 따른 등급과 날짜 미확인을 분리하며, 날짜 누락을 자동 확인 불가 조건으로 사용하지 않습니다.
실제 파이프라인이 읽는 basic 입력의 고정 기준일·이후 자료 차단 문구는 제거했습니다. acceptance와 합성 사례의 고정 날짜는 테스트 조건으로만 유지합니다.
이 수정은 1~4단계 산출물 보정이며 5단계 시장 전용 자동 검증이나 실제 LLM 품질 평가 완료를 의미하지 않습니다.

## 시장 5단계: 전용 오프라인 검증 추가

앞선 절의 시장 전용 자동 검증 미구현 기록은 이 절로 갱신합니다.
`app/evaluate_market.py`와 `tests/test_market_eval.py`를 추가했습니다.
기존 expectations.json의 13개 사례, 고정 등급 76개, 수동 검토 2개를 그대로 사용하며
새 등급 조건이나 그래프 노드를 추가하지 않습니다. 실행법은 시장 fixture README에 있습니다.

저장된 입력·근거 일치, 6항목 누락/중복, 등급 대조, 공통 인용 계약, 기술 간 잘못된 인용,
검색 이력·실패·미확인 상태를 검사합니다. planned-only의 채택 등급은 자동 정답으로 강제하지 않습니다.
인용 내용과 판단 사유의 의미, 이해당사자 표시·상충 설명 등은 기존 review_checks로 사람이 검토합니다.
자동 검사 통과와 무관하게 human_review_required를 유지합니다.

검증기 단위 테스트는 가공된 결과를 사용합니다. 실제 유료 LLM 평가·검색 품질 평가·최종 보고서 인수는
이 단계의 완료에 포함되지 않으며, 전체 설계나 공통 그래프의 차이를 해결했다고 선언하지 않습니다.

## 시장 재대조 후 보완: A.4·B.3·C.2

- A.4의 평가 범위를 시장 시스템 프롬프트에 명시했습니다. KIVI는 KV cache 양자화,
  ITME는 CXL 메모리를 KV cache 저장 계층으로 쓰는 접근의 대표 사례로 다룹니다.
  접근 전반의 동향과 선정 기술 자체의 채택·지원 근거는 C.2에 따라 구분합니다.
- B.3의 reference 활용과 C.2의 배경 근거 활용에 맞춰, 시장 검증기가 다른 기술명이라는
  이유만으로 배경·보조 문서 인용을 거부하던 제한을 수정했습니다. 해당 인용을 별도 사람 검토
  목록으로 반환하며, ID·Judge·기대 등급 검사는 유지합니다. 메타데이터만으로 인용의 의미를
  자동 승인하지 않으며 신규 등급 조건을 추가하지 않았습니다.
- C.2의 긍정·비판 자료 검색 요구를 시장 자료 정책과 basic/acceptance의 6개 질문에 반영했습니다.
  한쪽 자료만 제공되면 그 사실을 남기고, 실행 기록 없이 검색했다고 주장하지 않도록 했습니다.
  질문·프롬프트 반영만으로 검색 수행을 보장하지는 않습니다. 공통 검색의 양쪽 실행·기록 및
  종합의 gap 판단과 연결하는 작업은 담당 팀원과 통합할 사항으로 남습니다.

표 8의 12개 등급 조건과 기존 기대 판정은 유지합니다. 실제 LLM 평가와 사람의 원문 검토는 남아 있습니다.
