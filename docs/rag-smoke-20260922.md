## 발견한 문제

1. macOS arm64 / Python 3.11 / torch 2.14.0 환경에서 기본 병렬 설정으로 인덱싱을 시작하면 SIGSEGV가 발생했습니다. macOS 충돌 로그의 실행 스택은 `libomp.dylib`를 가리켰습니다. 아래 프로세스별 설정으로 인덱스 생성·검색·노드 실행을 완료했습니다. 정확한 패키지 조합 원인이나 모든 플랫폼의 해결책은 확정하지 않았습니다.
2. 실제 생성 결과가 mechanism rubric의 허용값을 따르지 않았고, 일부 주장은 근거 ID가 없었습니다. Judge가 한 주장에 그 주장이 인용하지 않은 ID를 반환한 경우도 공통 검사에서 거부했습니다.
3. 한계점 관련 두 주장은 unsupported로 판정됐습니다. 충분성 판단도 실제 근거가 모든 실험 조건을 담았는지 추가 검토가 필요합니다. 검색된 일부 원문에서 근거를 못 찾았다는 사실을 논문 전체에 언급이 없다는 주장으로 확대하면 안 됩니다.
4. unsupported/미확인이 포함된 경우의 현재 라우팅은 재검색을 우선합니다. 이번 실행은 검색 예산 소진 후 `추가 근거 필요`로 종료해, 함께 존재했던 형식 오류에 대한 fix 단계는 실행되지 않았습니다. 서브그래프 담당자가 검토할 동작이며 이번 두 검증 수정에 라우팅 변경을 섞지 않았습니다.

이번 점검은 기술 프롬프트와 공통 런타임의 실제 연결 문제를 드러냈습니다. TRL 두 필드 일치·Judge가 확인한 근거만 인정하는 수정은 별도로 반영하며, 그 수정만으로 위 출력 품질 문제가 해결됐다고 간주하지 않습니다.

## 재현 방법

각자 키가 있는 환경을 로드하고 실행합니다. 로컬 원문과 `uv sync --frozen --extra rag`가 필요합니다. 아래 스레드 설정은 해당 Mac에서 확인한 우회 방법이며 `.zshrc`나 팀 설정을 자동 변경하지 않습니다.

```bash
uv run --extra rag python -m app.index --check
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false \
  uv run --extra rag python -m app.index
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false \
  uv run --extra rag python -m app.run_node --node tech --mode rag --case acceptance
```

LangSmith를 사용하면 개인 `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`, `LANGSMITH_TRACING=true`를 설정합니다. 원문·캐시·키·실행 산출물은 Git에 올리지 않습니다. 실행마다 결과가 달라질 수 있으며 실제 API 비용이 발생합니다.

로컬 증거: `outputs/local/rag-smoke-20260922/retrieval.json`, `outputs/local/20260922T022026Z-tech-142ffa32/{run,input,result}.json`. 해당 파일은 실행한 개인 환경에만 있으며 이 문서의 결과를 팀원의 재현 결과로 대신 사용하지 않습니다.
